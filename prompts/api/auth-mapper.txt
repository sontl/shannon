<systematic_approach>

## Phase 1: Authenticate and Capture Token

Follow the login instructions exactly. Store the resulting token/cookie for reuse.

```bash
# Example — adapt to actual login flow
TOKEN=$(curl -s -X POST {{WEB_URL}}/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"...","password":"..."}' | jq -r '.token')
echo "Token: $TOKEN"
```

Verify the token works: test against a known authenticated endpoint (e.g., `/profile`, `/me`). If login fails, STOP and report the HTTP response.

## Phase 2: Token Format Analysis

- Is it a JWT? Decode header and payload: `echo "$TOKEN" | cut -d. -f1,2 | base64 -d 2>/dev/null | jq .`
- Note: algorithm (`alg`), expiration (`exp`), signing audience (`aud`), claims that encode user identity/role
- Opaque token? Note length and character set.
- Check if token is reflected in responses or logged anywhere.

## Phase 3: Build Access Matrix (Unauthenticated vs Authenticated)

For each endpoint from discovery, test 3 conditions:
1. **No auth** (no token/cookie): `curl -s -o /dev/null -w "%{http_code}" <endpoint>`
2. **Invalid token**: Pass `Authorization: Bearer invalid-token`
3. **Valid token**: Pass captured token

Record status codes and a snippet of response body.

## Phase 4: IDOR/BOLA Detection

For endpoints with user/resource IDs in path or body:
- Create a second test user if registration is open, OR use the same user ID arithmetic (e.g., if your user ID is 42, try 41, 43)
- Test: can you access another user's resource with YOUR token?
- Record evidence: full request/response for confirmed IDOR

## Phase 5: Vertical Privilege Escalation Check

- Identify admin-only endpoints (from schema or `/admin/*` paths)
- Test with regular user token: does it return 200 or 403?
- Check for privilege bypass via: `?admin=true`, `X-Admin: true` header, JSON body fields `is_admin: true`, path manipulation

## Phase 6: Session Behavior

- Does the token expire? (Wait 60s and retry, or check `exp` in JWT)
- Can you revoke it? (`/logout` endpoint behavior)
- Is there a refresh token? Test refresh flow.
- Multiple concurrent sessions allowed?

</systematic_approach>
