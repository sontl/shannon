<systematic_approach>

## Phase 1: Mass-Assignment Testing

For each POST/PUT/PATCH endpoint that accepts JSON, identify the documented field set from discovery/schema. Then send additional unexpected fields:

Common high-value mass-assignment fields:
- `is_admin`, `isAdmin`, `admin`, `role`, `user_type`, `permissions`
- `verified`, `email_verified`, `kyc_status`
- `plan`, `plan_type`, `subscription_tier`, `tier`
- `balance`, `credits`, `points`
- `created_at`, `updated_at`, `id`, `user_id`, `owner_id`

Example attack:
```bash
curl -X PUT {{WEB_URL}}/api/users/profile \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"test","is_admin":true,"plan_type":"enterprise"}'
```

Verify: re-fetch profile. Did `is_admin` stick? Did `plan_type` escalate?

## Phase 2: HTTP Response Injection (CRLF)

For parameters that may be reflected in response headers (redirects, Location, Set-Cookie):
- Test: `%0D%0ASet-Cookie:+injected=1`
- Test: `%0D%0A%0D%0A<script>alert(1)</script>` (response splitting)
- Look for `Location:` headers that echo user input

## Phase 3: Header Injection

For parameters that influence response headers:
- X-Content-Type-Options bypass
- Content-Disposition filename injection
- Cache-Control poisoning via `Host` header manipulation

## Phase 4: Content-Type Confusion

- Send JSON to XML-expecting endpoint and vice versa
- Parser differentials: `Content-Type: application/json` with XML body
- Check if the API MIME-sniffs user-controlled Content-Type
- Test `application/xml`, `text/xml`, `application/x-yaml`, `application/msgpack`

## Phase 5: Reflected Payload in API Response

If the API returns user-supplied data in JSON responses:
- Inject HTML: `<img src=x onerror=alert(1)>`
- Inject JavaScript strings: `"; alert(1); //`
- This is NOT XSS on the API itself, but flag it: downstream consumers (mobile apps, web UIs) may render unsanitized
- Severity: medium — depends on downstream consumers

## Phase 6: JSON Parser Issues

- Duplicate keys: `{"role":"user","role":"admin"}` — which wins?
- Integer overflow: `{"id": 999999999999999999999}`
- Unicode normalization: `{"user": "admin\u0000"}`
- Prototype pollution: `{"__proto__": {"isAdmin": true}}`, `{"constructor": {"prototype": {"isAdmin": true}}}`

## Phase 7: File Upload Content-Type

If file upload endpoints exist:
- Upload `.php`, `.jsp`, `.py`, `.html` with `Content-Type: image/jpeg`
- Magic byte bypass: `GIF89a\n<?php ... ?>`
- Polyglot files

</systematic_approach>
