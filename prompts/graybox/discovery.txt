<systematic_approach>
Execute all phases below. Do not skip any phase.

## Phase 1: Schema Ingestion (if schemas provided)

If schemas were provided in the context above, ingest them immediately:
- **OpenAPI / Swagger:** Fetch the schema URL with curl. Parse all paths, methods, and parameter definitions. This becomes your seed endpoint list.
- **GraphQL:** Send an introspection query (`{ __schema { types { name fields { name } } } }`) to the provided endpoint. Extract all query, mutation, and subscription names with their argument lists.

## Phase 2: Browser-Based Spidering (MANDATORY — primary signal source)

**This phase is your single richest signal. Do not skip it or shortcut it.**

1. Navigate to `{{WEB_URL}}` with the Playwright browser.
2. Collect all `<a href>`, `<form action>`, `<script src>`, and `<link href>` attributes from the DOM.
3. Click through all navigation menu items, tabs, and buttons that load new routes or trigger API calls. Submit forms with placeholder values to elicit XHR traffic.
4. Monitor the Network panel: capture every XHR/Fetch request URL, method, request headers, and request body structure.
5. Note authentication tokens or cookies present in requests (format only — do not use credentials you don't have).

## Phase 3: JavaScript Bundle Analysis

**Production bundles only.** A "bundle" is a built, minified asset that is actually served to end users — typically loaded via `<script src="/assets/index-<hash>.js">` or similar. Identify bundles by inspecting `<script>` tags or the Network panel from Phase 2. Their URLs end in `.js` (not `.jsx`/`.tsx`) and they sit under build-output paths like `/assets/`, `/static/js/`, `/dist/`, `/_next/static/`, etc.

**Forbidden inputs:** Do NOT fetch raw source files from a dev server (`/src/**`, `/app/**`, `/pages/**` returning `.jsx`/`.tsx`/`.ts`/`.vue`). They are dev-only, JIT-transformed, and not representative of running behavior. If the target is a Vite/webpack-dev-server/Next-dev instance with no production bundle present, **skip Phase 3 entirely** and rely on Phases 2, 4, and 6 instead — Phase 2 already captured every endpoint the running app actually calls.

1. From Phase 2's network log, list every `.js` URL whose path looks like a built bundle (see paths above).
2. For each bundle, download with curl and search for:
   - String patterns: `"/api/"`, `"/v1/"`, `"/v2/"`, `"graphql"`, `"fetch("`, `"axios."`, `"http"`, `"endpoint"`
   - Route definitions: framework-specific patterns (e.g., `router.get(`, `app.post(`, `path:`, `route:`)
   - Parameter names in URL templates (e.g., `:id`, `${userId}`, `{projectId}`)
3. Compile a candidate endpoint list from discovered strings.
4. When in doubt, prefer one extra Phase 2 click-through over guessing from minified code.

## Phase 4: Common Path Fuzzing

Based on the technology stack detected in Phase 2, fuzz for standard paths that may not be linked in the UI.
Test categories:
- **Health / Meta:** `/health`, `/api/health`, `/status`, `/ping`, `/version`, `/api/v1/`
- **Auth:** `/login`, `/logout`, `/register`, `/auth/token`, `/oauth/token`, `/api/auth/*`
- **Admin / Debug:** `/admin`, `/dashboard`, `/debug`, `/api/admin`, `/__debug__`, `/metrics`
- **Documentation:** `/api-docs`, `/swagger.json`, `/openapi.json`, `/graphql` (POST with introspection)
- **Common REST nouns** based on the app's domain (e.g., `/api/users`, `/api/projects`, `/api/files`)

For each candidate, issue a HEAD or GET request and record the HTTP status code. Only endpoints returning 200, 201, 301, 302, 401, or 403 are considered real — 404 responses are discarded.

## Phase 5: Authentication Mechanism Mapping

Identify how authentication works without logging in:
- What tokens are required? (Bearer JWT, session cookie, API key header?)
- What is the token format? (Observe Authorization header shape in unauthenticated vs authenticated requests if any session cookies exist.)
- Are there refresh token endpoints?
- Is there an SSO redirect flow?

## Phase 6: Prioritize Focus Areas

Review the developer focus hints. For each hinted path:
- Confirm the endpoint exists (probe it directly).
- Document its full parameter set by inspecting JS bundles or sending an OPTIONS request.
- Note if it requires authentication.
