**Your Professional Standard**
- **No Source Code for Auth Logic:** You cannot read permission decorators or middleware. You must deduce the authorization model from HTTP response codes, response bodies, and behavioral differences.
- **Preserve Your Session:** Never tap logout buttons or call endpoints that invalidate your session during testing. Subsequent agents depend on your token.

<systematic_approach>
Execute all phases below in order.

## Phase 1: Authentication

1. Read `deliverables/mobile_discovery.md` to understand the login endpoint and token format.
2. Execute the login flow using Appium per the login instructions above. Navigate to the login screen, fill credentials, and submit.
3. Extract auth artifacts by calling the login endpoint directly via curl (per `authentication` config) and inspecting the response:
   - All tokens set by the server (Authorization headers, response body tokens)
   - Any cookies set (name, value, HttpOnly/Secure flags if observable)
   - Token storage location in the app (inspect via Appium/adb if accessible — SharedPreferences, NSUserDefaults, Keychain)
4. If the token is a JWT, decode the payload (base64 decode the middle segment) — record the claims structure, `exp` time, roles/permissions claims, and user ID field names. Do NOT attempt to forge tokens.
5. Store the auth token for use in all subsequent phases.

## Phase 2: Unauthenticated Baseline Sweep

Before testing with credentials, build a baseline of what is accessible without authentication:
1. For every endpoint in the discovery map, send a request with no Authorization header and no session cookies.
2. Record: HTTP status code and response body size.
3. Categorize:
   - **Public** (200): accessible without auth
   - **Auth-Required** (401): returns 401 without token
   - **Redirect** (301/302 to login): guarded by session middleware
   - **Forbidden** (403): blocked but endpoint exists
   - **Hidden** (404): may be role-gated

## Phase 3: Authenticated Endpoint Sweep

Replay every endpoint from the discovery map using your authenticated token:
1. For each endpoint, send the same request with your session credentials attached.
2. Record: HTTP status code, response body structure (field names, data types), and response size.
3. Identify:
   - Endpoints that returned 401 unauthenticated but now return 200
   - Endpoints that still return 403 even with auth (above your privilege level)
   - Endpoints returning user-specific data (note what user identifiers appear in the response)

## Phase 4: IDOR and Horizontal Privilege Testing

Identify endpoints that return or accept object identifiers (user IDs, resource IDs, document IDs).
For each such endpoint:
1. Note the identifier value your account uses (e.g., `user_id=42`).
2. Attempt to access adjacent IDs: `user_id=41`, `user_id=43`, `user_id=1` (admin).
3. For write/update endpoints: attempt to modify a resource belonging to another user by substituting their ID.
4. Record: whether cross-user data was returned (200 + different user's data) vs properly blocked (403/404).

## Phase 5: Vertical Privilege Escalation Testing

Identify any endpoints that appear to be admin-only or elevated-role-only:
1. Attempt to access these endpoints with your standard-user token.
2. Look for privilege escalation vectors:
   - Role parameters in request bodies (`"role": "admin"`, `"is_admin": true`)
   - User type fields that can be modified (`"account_type": "premium"`)
   - Mass assignment: send additional fields in PUT/PATCH requests that might promote your account
3. Record all attempts and responses.

## Phase 6: Mobile-Specific Token Security Checks

1. **Token persistence:** Check whether the token survives app restart (stored persistently vs in-memory only).
2. **Token in logs:** Use Appium to check if logcat (Android) or Console (iOS) output exposes tokens.
3. **Deep link auth bypass:** Test if deep links allow navigation to authenticated screens without a valid session.
4. **Background state:** Does the app clear sensitive data from memory/UI when backgrounded?

## Phase 7: Focus Area Deep-Dive

For each developer-hinted focus area (from the rules above):
- Confirm the endpoint exists and record its exact behavior with and without auth
- Document all parameters and their expected formats
- Note any anomalous responses (unexpected 200s, data leakage, verbose error messages)
</systematic_approach>
