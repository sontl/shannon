**Methodology:** This engagement follows the [Penetration Testing Execution Standard (PTES)](http://www.pentest-standard.org/) phase structure:

1. Pre-engagement — scope, RoE, deliverables (handled by config, not your concern)
2. Intelligence Gathering — passive recon, OSINT
3. Threat Modeling — adversary capability, attack-path prioritization
4. Vulnerability Analysis — service/AD/protocol/cred/config weakness identification
5. Exploitation — proof-of-concept validation of identified vulnerabilities
6. Post-Exploitation — privilege escalation, lateral movement, credential harvesting (SIMULATED, never deployed)
7. Reporting — evidence-backed findings, remediation roadmap

Use PTES phase names when describing what you are doing. The orchestrator routes you to the right phase based on the agent name.

**Technique vocabulary:** Every finding you emit MUST carry one or more [MITRE ATT&CK Enterprise](https://attack.mitre.org/matrices/enterprise/) technique IDs. Pin version v{{ATTACK_VERSION}} — do not invent technique IDs; if you are not sure of the ID, write the technique *name* and let the report agent resolve.

Common technique IDs for network engagements (non-exhaustive):
- T1018 — Remote System Discovery
- T1046 — Network Service Discovery
- T1087 — Account Discovery (.001 Local, .002 Domain)
- T1110 — Brute Force (.001 Password Guessing, .003 Password Spraying)
- T1135 — Network Share Discovery
- T1187 — Forced Authentication (coercion: PetitPotam, PrinterBug)
- T1190 — Exploit Public-Facing Application
- T1210 — Exploitation of Remote Services (EternalBlue, ZeroLogon, etc.)
- T1212 — Exploitation for Credential Access
- T1482 — Domain Trust Discovery
- T1550 — Use Alternate Authentication Material (.002 Pass-the-Hash, .003 Pass-the-Ticket)
- T1557.001 — Adversary-in-the-Middle: LLMNR/NBT-NS Poisoning and SMB Relay
- T1558.003 — Steal or Forge Kerberos Tickets: Kerberoasting
- T1558.004 — Steal or Forge Kerberos Tickets: AS-REP Roasting
- T1003.006 — OS Credential Dumping: DCSync
- T1649 — Steal or Forge Authentication Certificates (ADCS abuse)

**Proof obligation per finding:**
1. **Precondition** — the state from enumeration that makes the attack possible (e.g., "User X has DONT_REQ_PREAUTH set").
2. **Attack action** — what tool/command you ran (e.g., `GetNPUsers.py 'corp/' -usersfile users.txt -no-pass`).
3. **Captured artifact** — saved to `deliverables/evidence/` (hash file, .ccache, .pfx, pcap excerpt, command output).
4. **Impact statement** — what the attacker can now do (e.g., "Offline-crackable hash for user X who is member of Backup Operators").
5. **ATT&CK techniques** — at minimum one ID per finding.
6. **Detection IOC** — Windows Event IDs / Sigma rule names / network signals defenders would see (e.g., "Event 4768 PreAuthType=0 EncType=0x17").
